### 마일스톤 레포 (`feat/paljapinsaju-checkout`, 커밋 안 함)
- 결제 후 돌아갈 주소 허용 목록에 팔자핀사주가 없었다 → **결제는 되는데 손님이 결과지로 못 돌아오는 출시 차단 문제.**
  환경변수 `NEXT_PUBLIC_TRUSTED_RETURN_ORIGINS`(쉼표 구분, https 만)로 추가할 수 있게 함.
- `brand=paljapinsaju` 로 들어온 결제만: "1회 결제" 표시, 팔자핀사주 이용약관·개인정보·환불정책 링크,
  "열람한 디지털콘텐츠는 청약철회 제한" 고지. 마일스톤 환불 요약은 숨김. 허용 목록을 통과한 returnUrl 일 때만 적용되므로
  주소를 조작해 다른 사이트 링크를 띄울 수 없다.
- 다른 상품(strength-test 등)은 화면 그대로 (로컬에서 둘 다 확인).

## 출시 구조 (2026-10-27 결정: DB 없이, 결제 한 번으로 끝)

예전 운영 DB(Supabase `cpxalgolpsebmctzeabo`)는 DNS 에서 사라져 있었다(삭제된 것으로 보임). 새 DB 를 만들지 않고 계정 없이 판다.

- `ACCOUNTS_ENABLED`(`src/lib/accounts.ts`) — Supabase 설정이 있을 때만 켜짐. 꺼지면 로그인·상담사 채팅·타로·별자리·궁합·마이페이지·관리자를
  메뉴에서 숨기고 proxy 가 홈으로 보낸다(채팅은 무료 체험으로, 고민 주제는 이어서). 서버는 빈 결과만 주는 비로그인 클라이언트로 동작.
- 홈 "분석 시작하기"·"지금 시작하기"와 고민 상담 카드가 채팅(=로그인 요구)으로 가던 것을 무료 체험으로. 운영에선 그동안 첫 버튼부터 로그인을 요구하고 있었다(로컬 목 모드에서만 체험으로 넘어감).
- 결제 확인: 결제할 때 결과지 ID 를 `resultId` 로 마일스톤에 넘기고, 확인 때 마일스톤이 돌려준 결과지·상품만 연다.
  DB 기록 없이도 주문번호를 다른 결과지에 다시 쓸 수 없다. (마일스톤 `purchases.result_id` 는 text, 운영 마일스톤이 결제→완료→기록까지 넘기는 것 확인)
- 템플릿의 가짜 후기("사용자 A/B/C") 섹션 삭제, FAQ·검색엔진 FAQ 를 계정 없는 구조에 맞춤.
